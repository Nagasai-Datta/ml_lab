stays higher. The memoryless policy never backs off: it continues to nudge about every other day, keeps
the person habituated, and its health score drifts down relative to the other two after day 10. The
memoryless planner cannot see the accumulating habituation, so it has no reason to stop.

poor domain in a habituated person can still justify a nudge when the cost is only 0.06.

8. Discussion
Why no learned policy beats the rule. The behaviour policy nudges only when a domain is poor, which
is close to what the simulator's reward favours; the rule also uses a single threshold that happens to align
with the cost of a nudge. Under such conditions the Bellman-optimal policy is not very different from the
rule, and estimation noise in 8,400 transitions is enough to offset any small advantage. The honest
summary is that the fatigue band restores parity with a strong expert rule. In practice an app's rule will be
less well matched, so the room for improvement could be larger - but the simulator cannot show that.
Design guidance. (1) Any intervention whose effect decays with exposure needs an exposure summary
in the state. It is cheap to compute from the notification log. (2) Check model-predicted against measured
advantage whenever a simulator or randomised holdout exists; a sign disagreement is a red flag that no
amount of data will fix. (3) Prefer an exposure summary with few levels: four bands were enough here,
and each added band multiplies the data requirement.
Algorithm choice. DP, Q-learning and Monte Carlo all benefit equally from the augmentation, so the
state definition matters more than the solver. With the correct state, Monte Carlo is competitive on this
short, 28-step horizon, unlike in longer-horizon problems where its variance dominates.

9. Limitations and threats to validity
   Habituation form. The simulator's habituation is a single exponential memory. Real habituation is
    person-specific and may recover or sensitise; a sufficient summary could need more than one
    number.
   Observable exposure. We assume the habituation band is computed from the log exactly. In
    practice it is a noisy proxy for the person's true state of attention.
   One nudge per day, no content. Real systems vary message content, timing and channel; our action
    set is a coarse abstraction.
   No engagement dynamics. People can disable notifications after too many nudges. Such drop-out
    would make over-nudging even worse than the simulator shows.
   Simulated, not clinical, evidence. All numbers come from stylised simulators written for this study.
    They demonstrate how the algorithms behave when the ground truth is known; they say nothing
    about the safety or benefit of any treatment in people.
   State aggregation. Continuous physiology is discretised into bands. Banding makes the process only
    approximately Markov, and part of the gap between the DP policy on the estimated model and the
    true optimum is a modelling gap rather than a sampling gap.
   Fixed-horizon episodes treated as stationary. Episodes end after a fixed number of steps but the
    state does not always contain the clock, so the estimated model treats termination as a constant
    hazard. This distorts absolute model values (not true-simulator scores) and is why model-based value
    estimates are compared only on a common oracle model.
   Behaviour policy. The logged data come from a single ε-noisy rule. Coverage of non-rule actions is
    therefore thin, which is exactly the offline-RL situation, and results depend on that coverage.
   Hand-set hyper-parameters. ε schedules, step sizes and the support threshold were fixed in
    advance and not tuned per paper.

10. Ethical considerations and future work
Ethics. No human data were used, so no consent or privacy issues arise in this study. If the method were
applied to real records, three safeguards would be essential: de-identification and governance approval of
the source data; a clinician-in-the-loop design in which the learned policy is advisory, with hard
guardrails on unsafe actions; and prospective, randomised or at least carefully monitored evaluation
before any deployment. Reinforcement learning from logs inherits the biases of the clinicians who
produced them, and may under-serve groups that are under-represented in the data; subgroup
performance should be reported alongside averages.

                                        Fatigue-aware nudging | Page 9
Future work. (1) Replace the exponential habituation by person-specific, possibly non-monotone
responsiveness and test whether a learned summary of exposure can replace the hand-built band; (2)
combine the fatigue band with the support-threshold and robust methods used for other conditions; (3)
run the adapter on a real wearable log and compare the model-predicted advantage of the fatigue-aware
policy to an A/B holdout, the only true test of the diagnostic proposed here.

11. Conclusion
A learner that treats each day as a fresh Markov state cannot see habituation. On a wearable-style
simulator, DP, Monte Carlo control and Q-learning without a fatigue band all over-nudge (22, 19 and 19
of 28 days) and underperform an expert rule; with a four-level habituation band they nudge about 10-12
days and match it. The model-predicted-versus-true advantage diagnostic shows that the memoryless
failure is a policy-induced distribution shift, so it persists with more data. The practical message is
simple: give the state a memory of recent exposure. The scientific caveat is equally simple: this is a
simulator study, and no learned policy outperformed the expert rule.

Appendix A. Anticipated reviewer questions
The following questions are the ones a reviewer or examiner is most likely to raise. Each answer is tied
to a number or figure produced by the code.
Q1. Why should I believe a simulator result about habituation?
   You should not believe it as a statement about people. It demonstrates a mechanism - a model that
   ignores exposure history is misled when logs come from a cautious policy - and measures how large
   the consequence can be when ground truth is known. The adapter provided lets the same analysis be
   run on real logs, where only model-based estimates are possible.
Q2. Is the fatigue band just an extra feature that adds information?
   Yes, and that is the point: it is the minimal piece of history that makes the dynamics approximately
   Markov. Table 4 shows its effect on policy ranking, not merely on fit.
Q3. Why did even the oracle memoryless DP lose to the rule?
   Because the model is wrong in a systematic way. The memoryless oracle predicts a +0.86 advantage
   over the rule and delivers -1.17. The error is not statistical noise: it is the habituation distribution that
   differs between behaviour and learned policy.
Q4. Are the four habituation bands optimal?
   They were chosen in advance and not tuned. A finer partition would reduce approximation error and
   increase data requirements; testing 3, 4 and 6 bands is the obvious sensitivity analysis, and the code
   accepts any bin edges.
Q5. Why does the rule beat the learned policies, and is that a problem for your claim?
   It limits the claim. We claim only that augmentation prevents a failure and restores parity with the
   rule; we do not claim superiority. The rule matches the simulator's cost structure well, which is a
   favourable case for the baseline.

    class Nudge(Domain):
        name = "nudge"
        nA, gamma, max_steps = 4, 0.97, 28
        info_keys = ["health", "nudges"]
        action_labels = ["none", "sleep", "activity", "stress"]
        behavior_eps = 0.3

         def __init__(self, memory=True):
             self.memory = memory
             self.nS = 27 * (4 if memory else 1)

        def _s(self):
            b = (band(self.sl, [0.4, 0.65]) * 3 + band(self.ac, [0.4, 0.65])) * 3 +
    band(self.st, [0.4, 0.65])
            if not self.memory:
                return b
            return b * 4 + band(self.h, [0.5, 1.2, 2.0])

         def reset(self, rng):
             self.sl, self.ac, self.st = (float(np.clip(rng.normal(0.5, 0.15), 0, 1)),
                                          float(np.clip(rng.normal(0.4, 0.15), 0, 1)),
                                          float(np.clip(rng.normal(0.55, 0.15), 0, 1)))
             self.h, self.t = 0.0, 0
             return self._s()

        def step(self, a, rng):
            m = float(np.exp(-0.9 * self.h))
            n = lambda: rng.normal(0, 0.08)
            sl = self.sl + 0.25 * (0.55 - self.sl) + 0.5 * m * (a == 1) * (1 - self.sl) +
    0.05 * (self.ac - 0.4) + n()
            ac = self.ac + 0.25 * (0.40 - self.ac) + 0.55 * m * (a == 2) * (1 - self.ac) +
    n()
            st = self.st + 0.20 * (0.50 - self.st) - 0.5 * m * (a == 3) * self.st + 0.15 *
    (0.5 - self.sl) + n()
            self.sl, self.ac, self.st = (float(np.clip(x, 0, 1)) for x in (sl, ac, st))
            self.h = 0.7 * self.h + float(a > 0)
            self.t += 1
            health = (self.sl + self.ac + (1 - self.st)) / 3.0
            r = health - 0.06 * (a > 0)
            return self._s(), r, self.t >= self.max_steps, dict(health=health,
    nudges=float(a > 0)), 1

         def rule(self, s):
             b = s // 4 if self.memory else s
             sl, ac, st = b // 9, (b // 3) % 3, b % 3
             # nudge the worst domain if it is in the lowest band
             worst = min((sl, 1), (ac, 2), (2 - st, 3))
             return worst[1] if worst[0] == 0 else 0

    def build_mdp(data, dom, weights=None, chan=None, min_n=10, term_prior=1.0):
        """Empirical (maximum-likelihood) MDP from logged transitions.
        (s,a) pairs observed fewer than min_n times are completed pessimistically: they go
        to the absorbing terminal state with the worst reward seen in the data."""
        nS, nA = dom.nS, dom.nA
        T = nS
        w = np.ones(len(data["s"])) if weights is None else np.asarray(weights, float)
        s, a = data["s"], data["a"]
        s2 = np.where(data["done"] > 0, T, data["s2"])
        N = np.zeros((nS + 1, nA, nS + 1))
        np.add.at(N, (s, a, s2), w)


                                  Fatigue-aware nudging | Page 12
    n = N.sum(2)
    Rsum = np.zeros((nS + 1, nA))
    np.add.at(Rsum, (s, a), w * data["r"])
    Gsum = np.zeros((nS + 1, nA, nS + 1))
    np.add.at(Gsum, (s, a, s2), w * dom.gamma ** data["dur"])
    m = MDP()
    m.nS, m.nA, m.gamma = nS, nA, dom.gamma
    m.n = n
    m.N = N
    seen = n >= min_n          # support constraint: thinly observed (s,a) are
completed pessimistically
    n_eff = n + term_prior        # one pseudo-observation of absorption guards against
'immortal' loops
    P = np.zeros_like(N)
    P[seen] = N[seen] / n_eff[seen][:, None]
    P[seen, T] += term_prior / n_eff[seen]
    G = np.full_like(N, dom.gamma)
    nz = N > 0
    G[nz] = Gsum[nz] / N[nz]
    R = np.zeros((nS + 1, nA))
    R[seen] = Rsum[seen] / n_eff[seen]
    rmin = float(data["r"].min())
    m.rmin, m.rmax = rmin, float(data["r"].max())
    P[~seen, T] = 1.0
    R[~seen] = rmin
    P[T, :, :] = 0.0
    P[T, :, T] = 1.0
    R[T, :] = 0.0
    m.P, m.G, m.R = P, G, R
    m.PG = P * G
    # reward channels
    m.Rc = {}
    for c in (chan if chan is not None else dom.chan):
        cs = np.zeros((nS + 1, nA))
        np.add.at(cs, (s, a), w * data[c])
        cr = np.zeros((nS + 1, nA))
        cr[seen] = cs[seen] / n_eff[seen]
        m.Rc[c] = cr
    # start distribution = first state of every episode
    first = data["t"] == 0
    mu = np.bincount(data["s"][first], minlength=nS + 1).astype(float)
    m.mu = mu / mu.sum()
    m.visits = (n * seen).sum(1)[:nS]
    m.seen = seen
    m.Rsum = Rsum
    return m


def value_iteration(m, R=None, mask=None, tol=1e-9, max_iter=20000, penalty=None):
    R = m.R if R is None else R
    if penalty is not None:
        R = R - penalty
    V = np.zeros(m.nS + 1)
    for _ in range(max_iter):
        Q = _q(m, V, R)
        if mask is not None:
            Q = np.where(mask, Q, -1e18)
        Vn = Q.max(1)
        Vn[m.nS] = 0.0
        if np.abs(Vn - V).max() < tol:
            V = Vn
            break
        V = Vn
    Q = _q(m, V, R)
    if mask is not None:
        Q = np.where(mask, Q, -1e18)
    pi = Q.argmax(1)[:m.nS]
    return pi, V, Q


def q_learning(m, rng, steps, eps_fn=eps_exp, alpha0=1.0, alpha_min=0.02,
               q0=0.0, mask=None, n_ckpt=25, max_len=200, ckpt_fn=None):

    ckpt_fn = ckpt_fn or (lambda p: J(m, p))

   Q[nS] = 0.0

   ck = np.unique(np.linspace(0, steps, n_ckpt + 1).astype(int))

           curve.append((k, ckpt_fn(pi)))

       tgt = r + (0.0 if s2 == nS else g * Q[s2].max() if mask is None
                   else g * np.where(mask[s2], Q[s2], -1e18).max())
       cnt[s, a] += 1

       Q[s, a] += al * (tgt - Q[s, a])
       ep_t += 1
       if s2 == nS or ep_t >= max_len:
           s, ep_t = smp.start(), 0
       else:
           s = s2
   pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
   return pi, Q, np.array(curve)


def mc_control(m, rng, steps, eps_fn=eps_exp, q0=0.0, mask=None, n_ckpt=25,
                max_len=200, ckpt_fn=None):
    """first-visit Monte Carlo control with epsilon-soft behaviour policy and
    incremental-average updates."""
    nS, nA = m.nS, m.nA
    ckpt_fn = ckpt_fn or (lambda p: J(m, p))
    Q = np.full((nS + 1, nA), q0)
    Q[nS] = 0.0
    N = np.zeros((nS + 1, nA))
    smp = Sampler(m, rng)
    ck = np.unique(np.linspace(0, steps, n_ckpt + 1).astype(int))
    curve = []
    used, ci = 0, 0
    while True:
        while ci < len(ck) and used >= ck[ci]:
            pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
            curve.append((ck[ci], ckpt_fn(pi)))
            ci += 1
        if used >= steps:
            break
        s = smp.start()
        traj = []
        for _ in range(max_len):
            if rng.random() < eps_fn(used + len(traj), steps):
                 a = _explore(rng, s, nA, mask)
            else:
                 a = _greedy(Q, s, mask)
            s2, r, g = smp.step(s, a)
            traj.append((s, a, r, g))
            s = s2
            if s2 == nS:
                 break
        used += len(traj)
        # returns, backwards; first-visit
        Gret = 0.0
        rets = []
        for (s_, a_, r_, g_) in reversed(traj):
            Gret = r_ + g_ * Gret
            rets.append(Gret)
        rets.reverse()
