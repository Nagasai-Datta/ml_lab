oracle model's value of the same policy in every replicate (mean optimism gap -37.2). This is a code-
level reading, not a tested explanation, but it implies that the model scale is a pessimistic and distorted
version of the true scale; we use it only to compare learning speed.

7.3 Does the model-scale metric predict true return?
Learning efficiency is measured on the model scale, but what matters is true return. For each learner we
ranked the five schedules by their AUC and by the true return of the final policy on nominal data (Table
5). For Q-learning the two rankings agree exactly (Spearman correlation +1.00 over five schedules); for
MC they hardly agree (+0.30). With only five points no p-value is reported and the numbers are
descriptive. The best schedule by true return is eps exp. decay for Q-learning (true return 169.5) and
eps=0.1 const for MC (167.8), and the worst is Near-greedy (0.02) (161.2) and eps exp. decay (161.4).
The exponential decay schedule is the best for Q-learning and the worst for MC, and across the five
schedules the true-return ranks of the two learners have a correlation of -0.90.
How much of this is signal? The same learner with the exponential schedule also appears in the
benchmark, with different data draws (seeds 1000 to 1004 against 700 to 705) and more evaluation
episodes (300 against 120): Q-learning scored 164.4 there and 169.5 here (+5.1), and MC 166.6 there and
161.4 here (-5.2). Based on the code these are the same configuration, so differences of about 5 units
arise from the data draws and the evaluation sample alone. The spread of true returns across schedules is
8.3 for Q-learning and 6.5 for MC, which is 1.6 and 1.2 times that discrepancy, so the data do not
establish that any schedule changes true return, and the opposite orderings of the two learners are
consistent with noise.

8. Discussion
What the study shows. (1) Learners trained on 150 episodes are ahead of the overbooking rule in the
true simulator by +1.9 to +6.3 units on average, with only MC clearly so (p = 0.036), while a model
fitted to ten times the data is ahead by +18.7, which points to data coverage rather than the learner as the
main barrier (we did not vary the data volume continuously). (2) On the fitted model every schedule
converges to about the same value, and none reaches 90% of the possible improvement (0 of 60 runs).
(3) The one clearly resolved schedule effect is that a near-greedy Q-learner learns more slowly. (4) The
learned policies are ahead of the rule at the nominal rate and by a larger average margin when no-shows
fall (8.0 against 4.8; all 10 of 10 configurations), and level with it when no-shows rise.
What it does not show. It does not show that exploration schedules matter for final performance: the
final model-scale values are all within 0.13 of the behaviour policy's, and the true-return differences
across schedules are comparable to the run-to-run discrepancy for the same configuration. It does not
show that the model-scale metric is a good proxy for true return; its sign disagrees with the true
comparison, and its schedule ranking correlates with true return for Q-learning (+1.00) but hardly for MC
(+0.30). And it does not show which states drive the robustness result.
Practical use. Because exploration inside a fitted model does not collect new data, practitioners should
spend effort on what generates the log. A behaviour policy with deliberate variation in the number of
extra bookings, run at low stakes, would give the learner support for the actions the optimum uses; the
exploration schedule of the learner cannot substitute for that. For deployment the shift study suggests a
cheap sanity check: re-evaluate a learned policy against the existing rule under plausible no-show shifts
and report the range, not the nominal value alone.

9. Limitations and threats to validity
   Few replicates and no intervals for shift. The schedule study uses 6 replicates (t-interval factor
    1.31) and the shift table stores no intervals; the DP entry is one replicate.
   Unequal evaluation sizes. Rule and DP in the shift table use 300 evaluation episodes, the learners
    120 per run; the benchmark and the schedule study use different data seeds.
   A model-scale metric. Learning efficiency is measured on the oracle model, which is pessimistic by
    construction for pairs with fewer than 10 observations; the AUC also contains a common step-0
    offset of -0.122. The ranking of schedules on this scale need not match the ranking in the clinic.
   Exploration inside a model. The schedules sample from the fitted MDP and cannot reveal unlogged
    state-action pairs, so the study cannot say anything about exploration in the real environment, where
    a clinic would face costs of trying.
   Assumed no-show structure. The shift is a constant offset to the no-show rate; real shifts also
    change who is booked and the waiting-list inflow. The simulator's reward weights (3 for overtime,
    0.4 for waiting) are invented.
   Simulated, not clinical, evidence. All numbers come from stylised simulators written for this study.
    They demonstrate how the algorithms behave when the ground truth is known; they say nothing
    about the safety or benefit of any treatment in people.
   State aggregation. Continuous physiology is discretised into bands. Banding makes the process only
    approximately Markov, and part of the gap between the DP policy on the estimated model and the
    true optimum is a modelling gap rather than a sampling gap.
   Fixed-horizon episodes treated as stationary. Episodes end after a fixed number of steps but the
    state does not always contain the clock, so the estimated model treats termination as a constant
    hazard. This distorts absolute model values (not true-simulator scores) and is why model-based value
    estimates are compared only on a common oracle model.
   Behaviour policy. The logged data come from a single ε-noisy rule. Coverage of non-rule actions is
    therefore thin, which is exactly the offline-RL situation, and results depend on that coverage.



                                Clinic overbooking, exploration and shift | Page 10
   Hand-set hyper-parameters. ε schedules, step sizes and the support threshold were fixed in
    advance and not tuned per paper.

10. Ethical considerations and future work
Ethics. No human data were used, so no consent or privacy issues arise in this study. If the method were
applied to real records, three safeguards would be essential: de-identification and governance approval of
the source data; a clinician-in-the-loop design in which the learned policy is advisory, with hard
guardrails on unsafe actions; and prospective, randomised or at least carefully monitored evaluation
before any deployment. Reinforcement learning from logs inherits the biases of the clinicians who
produced them, and may under-serve groups that are under-represented in the data; subgroup
performance should be reported alongside averages.
Future work. (1) Add an exploration-aware behaviour policy that deliberately varies the extra bookings
and test whether the learners then close the gap to the oracle; (2) store per-replicate learning curves and
shift results to attach intervals and paired tests; (3) evaluate the oracle and a DP policy under shift, and a
policy trained on shifted data, to measure the cost of a stale model; (4) compare against a model-based
safeguard such as a pessimistic penalty in the supported part of the space; (5) apply the adapter to a real
no-show table, where overtime and waiting would need to be defined from visit timestamps.

11. Conclusion
On a simulated clinic, DP, MC and Q-learning trained on 150 logged days scored 162.2, 166.6 and 164.4
against 160.3 for a conservative overbooking rule and 179.0 for DP trained on ten times as much data.
Five exploration schedules gave learning curves that all plateaued at the same model value: none reached
90% of the possible improvement (0 of 60), only the near-greedy Q-learner was clearly slower, and the
ordering of schedules on true return differed between learners and was comparable in size to the seed-to-
seed discrepancy. The learned policies lost less than the rule when no-shows fell by 0.05 (all 10 of 10
configurations were ahead) and matched it when they rose by 0.08. These are simulator results, not
evidence about real clinics.

Appendix A. Anticipated reviewer questions
The following questions are the ones a reviewer or examiner is most likely to raise. Each answer is tied
to a number or figure produced by the code.
Q1. Why does no schedule reach 90% of the optimum?
    The learners solve a fitted model whose DP solution is worth about 122.7 on the oracle model,
    against a rule value of 125.6 and an optimum of 150.0. They converge to that solution (plateaus
    122.4 and 123.3), so the target is out of reach for any schedule; the limit is the support of the logged
    data, not exploration.
Q2. If exploration does not matter, why is near-greedy Q-learning slower?
    Near-greedy Q-learning has a mean AUC of -0.54 against -0.05 for the best schedule, and a plausible
    reason (not tested separately) is that it tries few actions early and needs many steps to correct its
    initial values. That is a speed effect within a fixed model; it disappears from the final values, which
    are all indistinguishable from zero.
Q3. Why do the model-scale and true-simulator comparisons disagree?
    The model treats rarely logged pairs as absorbing with the worst reward, so it undervalues every
    policy by 29 to 43 units and penalises choices the data do not support. On that scale the learners are
    2.3 to 3.2 below the rule, while in the true simulator they are ahead of it. The model scale is useful
    for learning speed, not for deciding which policy is better.
Q4. Can we conclude that exponential decay is best for Q-learning?

                                 Clinic overbooking, exploration and shift | Page 11
    No. Its true return in the schedule study (169.5) differs by 5.1 from the same configuration in the
    benchmark (164.4), which is comparable to the 8.3-unit spread across all five Q-learning schedules,
    and the same schedule is the worst for MC.
Q5. Is the robustness result a reason to deploy the learned policy?
    No. It is a simulated shift of a single parameter, with no intervals, evaluated on a policy that differs
    from the rule in few states. It shows that the learned policies do not lose more than the rule when no-
    shows fall, in all 10 of 10 configurations, and nothing more.
Q6. Why does the oracle score so much more than the learners?
    With 1,500 episodes the high-overbooking actions are supported (about 30 visits per pair against
    3.0), and the oracle uses +3 or +4 in 26 states. The learners use them in at most 4.

    def build_mdp(data, dom, weights=None, chan=None, min_n=10, term_prior=1.0):
        """Empirical (maximum-likelihood) MDP from logged transitions.
        (s,a) pairs observed fewer than min_n times are completed pessimistically: they go
        to the absorbing terminal state with the worst reward seen in the data."""
        nS, nA = dom.nS, dom.nA
        T = nS
        w = np.ones(len(data["s"])) if weights is None else np.asarray(weights, float)
        s, a = data["s"], data["a"]
        s2 = np.where(data["done"] > 0, T, data["s2"])
        N = np.zeros((nS + 1, nA, nS + 1))
        np.add.at(N, (s, a, s2), w)
        n = N.sum(2)
        Rsum = np.zeros((nS + 1, nA))
        np.add.at(Rsum, (s, a), w * data["r"])
        Gsum = np.zeros((nS + 1, nA, nS + 1))
        np.add.at(Gsum, (s, a, s2), w * dom.gamma ** data["dur"])
        m = MDP()
        m.nS, m.nA, m.gamma = nS, nA, dom.gamma
        m.n = n
        m.N = N
        seen = n >= min_n           # support constraint: thinly observed (s,a) are
    completed pessimistically
        n_eff = n + term_prior        # one pseudo-observation of absorption guards against
    'immortal' loops
        P = np.zeros_like(N)
        P[seen] = N[seen] / n_eff[seen][:, None]


                            Clinic overbooking, exploration and shift | Page 14
   P[seen, T] += term_prior / n_eff[seen]
   G = np.full_like(N, dom.gamma)
   nz = N > 0
   G[nz] = Gsum[nz] / N[nz]
   R = np.zeros((nS + 1, nA))
   R[seen] = Rsum[seen] / n_eff[seen]
   rmin = float(data["r"].min())
   m.rmin, m.rmax = rmin, float(data["r"].max())
   P[~seen, T] = 1.0
   R[~seen] = rmin
   P[T, :, :] = 0.0
   P[T, :, T] = 1.0
   R[T, :] = 0.0
   m.P, m.G, m.R = P, G, R
   m.PG = P * G
   # reward channels
   m.Rc = {}
   for c in (chan if chan is not None else dom.chan):
       cs = np.zeros((nS + 1, nA))
       np.add.at(cs, (s, a), w * data[c])
       cr = np.zeros((nS + 1, nA))
       cr[seen] = cs[seen] / n_eff[seen]
       m.Rc[c] = cr
   # start distribution = first state of every episode
   first = data["t"] == 0
   mu = np.bincount(data["s"][first], minlength=nS + 1).astype(float)
   m.mu = mu / mu.sum()
   m.visits = (n * seen).sum(1)[:nS]
   m.seen = seen
   m.Rsum = Rsum
   return m


def value_iteration(m, R=None, mask=None, tol=1e-9, max_iter=20000, penalty=None):
    R = m.R if R is None else R
    if penalty is not None:
        R = R - penalty
    V = np.zeros(m.nS + 1)
    for _ in range(max_iter):
        Q = _q(m, V, R)
        if mask is not None:
            Q = np.where(mask, Q, -1e18)
        Vn = Q.max(1)
        Vn[m.nS] = 0.0
        if np.abs(Vn - V).max() < tol:
            V = Vn
            break
        V = Vn
    Q = _q(m, V, R)
    if mask is not None:
        Q = np.where(mask, Q, -1e18)
    pi = Q.argmax(1)[:m.nS]
    return pi, V, Q


def q_learning(m, rng, steps, eps_fn=eps_exp, alpha0=1.0, alpha_min=0.02,
                q0=0.0, mask=None, n_ckpt=25, max_len=200, ckpt_fn=None):

            curve.append((k, ckpt_fn(pi)))

   return pi, Q, np.array(curve)


def mc_control(m, rng, steps, eps_fn=eps_exp, q0=0.0, mask=None, n_ckpt=25,
                max_len=200, ckpt_fn=None):
    """first-visit Monte Carlo control with epsilon-soft behaviour policy and
    incremental-average updates."""
    nS, nA = m.nS, m.nA
    ckpt_fn = ckpt_fn or (lambda p: J(m, p))
    Q = np.full((nS + 1, nA), q0)
    Q[nS] = 0.0
    N = np.zeros((nS + 1, nA))
    smp = Sampler(m, rng)
    ck = np.unique(np.linspace(0, steps, n_ckpt + 1).astype(int))
    curve = []
    used, ci = 0, 0
    while True:
        while ci < len(ck) and used >= ck[ci]:
            pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
            curve.append((ck[ci], ckpt_fn(pi)))
            ci += 1
        if used >= steps:
            break
        s = smp.start()
        traj = []
        for _ in range(max_len):
            if rng.random() < eps_fn(used + len(traj), steps):
                 a = _explore(rng, s, nA, mask)
            else:
                 a = _greedy(Q, s, mask)
            s2, r, g = smp.step(s, a)
            traj.append((s, a, r, g))
            s = s2
            if s2 == nS:
                 break
        used += len(traj)
        # returns, backwards; first-visit
        Gret = 0.0
        rets = []
        for (s_, a_, r_, g_) in reversed(traj):
            Gret = r_ + g_ * Gret
            rets.append(Gret)
        rets.reverse()
        seen = set()
        for (s_, a_, _, _), G_ in zip(traj, rets):
            if (s_, a_) in seen:
                 continue
            seen.add((s_, a_))
            N[s_, a_] += 1
            Q[s_, a_] += (G_ - Q[s_, a_]) / N[s_, a_]
    pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
    return pi, Q, np.array(curve)
