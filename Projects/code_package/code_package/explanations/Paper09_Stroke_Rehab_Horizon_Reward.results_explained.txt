8. Discussion
What the study shows. (1) With a weekly reward, standard learners improve on a fatigue-band rule at
every horizon (9 of 9 combinations significantly above it), but capture a decreasing share of the
achievable improvement as the horizon grows (DP 83% to 38%). (2) With a terminal reward, none is
significantly above the rule, 5 of 9 are significantly below it, and MC's policies are severely worse and
unsafe. (3) The oracle with ten times the data is also below the rule at 6 and 12 weeks under the sparse
reward, so the failure is not only a sample-size effect. (4) On the fitted model no run reached 90% of the
optimum (0 of 60), and Q-learning's final value declines with the horizon.
Why sparse rewards fail here. The dense and sparse returns are the same quantity up to discounting.
For the rule the sparse return divided by the total gain is 0.9752, 0.9464, 0.8911 at 6, 12 and 24 weeks
against 0.9752, 0.9464, 0.8911 for gamma^(H−1), so the true objectives agree to floating-point precision
(largest difference 2e-16). The difference is therefore informational: a dense reward tells the learner
which week contributed the gain, while a terminal reward gives one noisy number per course. Three
mechanisms are plausible and not mutually exclusive: variance of the terminal return for MC; slow value
propagation for Q-learning over long horizons; and the hidden-history term of Eq. (6) in the model,
which would affect DP as well. The pattern of results is consistent with all three (MC worst, Q-learning
intermediate and DP the least affected of the learners, yet the oracle also failing at shorter horizons), but
the experiment does not separate them, and the oracle failure is the observation that most needs an
explanation.
What it does not show. It does not show that horizon alone is harmful: the share captured by MC at 24
weeks (59%) is higher than at six (42%). It does not isolate why the sparse oracle fails. It does not show
that a particular reward is right clinically: the weekly gain is a score change and the injury penalty is
invented. And, because the summaries stored in results.json have no per-replicate values, it relies on
interval-based comparisons between learners rather than paired tests (except for the stored MC-minus-Q-
learning test).
Practical use. A programme designer who can observe interim progress should use it: when a terminal
outcome is the only signal, the experiments suggest checking the learned policy against the existing rule
before anything else, and preferring a model-based solver to Monte Carlo returns. A sparse-reward
pipeline should also report an oracle-style check (the same method with much more data), because a
failure of that check points to the formulation and not to the learner.

9. Limitations and threats to validity
   Few replicates and stored summaries. 5 replicates (t-interval factor 1.42); results.json stores means
    and intervals but not per-replicate values, so paired tests against the rule are not available and the
    comparisons use stored intervals. Learning curves, policies and agreement are available only as
    figures.
   One replicate in the policy figures. The policy maps show the first replicate at H = 12 and cannot
    be generalised to the averages.
   Hidden-history hypothesis untested. Eq. (6) is a reading of the code. We did not construct a variant
    whose state contains the initial score or the progress so far, which would be the direct test.
   Rule is a single policy. The rule's return has no replicate variation, so differences from the rule are
    judged by the learner's interval only.
   Invented dynamics and penalties. The gain, fatigue and injury equations, and the 2.5-point injury
    penalty, are chosen by hand; different values could change which reward type is easier.
   Simulated, not clinical, evidence. All numbers come from stylised simulators written for this study.
    They demonstrate how the algorithms behave when the ground truth is known; they say nothing
    about the safety or benefit of any treatment in people.



                                 Rehabilitation horizon and sparse reward | Page 10
   State aggregation. Continuous physiology is discretised into bands. Banding makes the process only
    approximately Markov, and part of the gap between the DP policy on the estimated model and the
    true optimum is a modelling gap rather than a sampling gap.
   Fixed-horizon episodes treated as stationary. Episodes end after a fixed number of steps but the
    state does not always contain the clock, so the estimated model treats termination as a constant
    hazard. This distorts absolute model values (not true-simulator scores) and is why model-based value
    estimates are compared only on a common oracle model.
   Behaviour policy. The logged data come from a single ε-noisy rule. Coverage of non-rule actions is
    therefore thin, which is exactly the offline-RL situation, and results depend on that coverage.
   Hand-set hyper-parameters. ε schedules, step sizes and the support threshold were fixed in
    advance and not tuned per paper.

10. Ethical considerations and future work
Ethics. No human data were used, so no consent or privacy issues arise in this study. If the method were
applied to real records, three safeguards would be essential: de-identification and governance approval of
the source data; a clinician-in-the-loop design in which the learned policy is advisory, with hard
guardrails on unsafe actions; and prospective, randomised or at least carefully monitored evaluation
before any deployment. Reinforcement learning from logs inherits the biases of the clinicians who
produced them, and may under-serve groups that are under-represented in the data; subgroup
performance should be reported alongside averages.
Future work. (1) Add the initial score or the accumulated improvement to the state and test whether the
sparse-reward oracle then beats the rule; (2) add a potential-based shaped reward with a partial signal and
measure how much of the gap closes; (3) vary the amount of logged data at each horizon to separate
coverage from compounding error; (4) store per-replicate returns so that paired tests against the rule are
possible; (5) apply the adapter to a real rehabilitation table, where interim functional scores would define
the dense reward.

11. Conclusion
In a simulated stroke-rehabilitation programme, DP, MC and Q-learning trained on 800 logged courses
were significantly above a fatigue-band rule at 6, 12 and 24 weeks when rewarded weekly (by 1.4 to 6.9
units), but captured a share of the oracle's headroom that fell with the horizon for DP and Q-learning
(83% to 38% for DP). With a terminal reward none was significantly above the rule, MC was far below it
with up to 9.5 injury weeks per course, and the oracle DP was below the rule at 6 and 12 weeks, even
though the two rewards define almost the same true objective. These are simulator results, not clinical
evidence, and the reasons for the sparse-reward failure remain hypotheses.

Appendix A. Anticipated reviewer questions
The following questions are the ones a reviewer or examiner is most likely to raise. Each answer is tied
to a number or figure produced by the code.
Q1. If dense and sparse rewards are the same objective, why do the results differ so much?
    They are the same in the true process (the rule's sparse return over its total gain is 0.9464 against
    gamma^11 = 0.9464 at H = 12), but not in what can be estimated: a terminal reward provides one
    noisy number per course, and the model's last-week reward includes a hidden-history term (Eq. 6).
    The results show the difference but do not isolate which mechanism produces it.
Q2. Why is the oracle DP below the rule under the sparse reward?
    It scores 3.91 and 3.66 against 4.15 and 5.20 at 6 and 12 weeks, with 2.14 injury weeks at 12. With
    ten times the data and an exact solver, a sample-size explanation does not apply, which points to the
    formulation. We offered the hidden-history term as a candidate but did not test it.

                                Rehabilitation horizon and sparse reward | Page 11
Q3. Does a longer horizon hurt learning?
   For DP and Q-learning under a dense reward the share of headroom captured falls (83%, 62%, 38%
   for DP) and Q-learning's normalised value falls (0.71 to 0.31); for MC it does not. Under a sparse
   reward the decline is much steeper (0.48 to -1.81 for Q-learning).
Q4. Is MC just a worse algorithm?
   Not uniformly. It is the weakest learner at six weeks under a dense reward (5.60 against 6.96 for DP)
   and the strongest at 24 weeks (14.85 against 12.40), and it is far worse than the others under a sparse
   reward.
Q5. Can these results guide a real rehabilitation programme?
   No. The dynamics, the injury rule and the penalty are invented; the study asks how reward design
   and horizon affect learning algorithms, and finds that a terminal-only reward is a hazard even when
   the true objective is unchanged.
Q6. Why were no run able to reach 90% of the optimal improvement?
   Under the dense reward the best final normalised value is 0.71; the fitted model has few supported
   off-rule pairs (about 2.8 visits per pair with 800 episodes), so the learned policy plausibly cannot
   adopt many actions the optimum uses (not tested). The plateaus in Figure 2 are reached early, so
   more steps would not change this.

    def build_mdp(data, dom, weights=None, chan=None, min_n=10, term_prior=1.0):
        """Empirical (maximum-likelihood) MDP from logged transitions.
        (s,a) pairs observed fewer than min_n times are completed pessimistically: they go
        to the absorbing terminal state with the worst reward seen in the data."""
        nS, nA = dom.nS, dom.nA
        T = nS
        w = np.ones(len(data["s"])) if weights is None else np.asarray(weights, float)
        s, a = data["s"], data["a"]
        s2 = np.where(data["done"] > 0, T, data["s2"])
        N = np.zeros((nS + 1, nA, nS + 1))
        np.add.at(N, (s, a, s2), w)
        n = N.sum(2)
        Rsum = np.zeros((nS + 1, nA))
        np.add.at(Rsum, (s, a), w * data["r"])
        Gsum = np.zeros((nS + 1, nA, nS + 1))
        np.add.at(Gsum, (s, a, s2), w * dom.gamma ** data["dur"])
        m = MDP()
        m.nS, m.nA, m.gamma = nS, nA, dom.gamma
        m.n = n
        m.N = N
        seen = n >= min_n           # support constraint: thinly observed (s,a) are
    completed pessimistically
        n_eff = n + term_prior        # one pseudo-observation of absorption guards against
    'immortal' loops
        P = np.zeros_like(N)
        P[seen] = N[seen] / n_eff[seen][:, None]
        P[seen, T] += term_prior / n_eff[seen]
        G = np.full_like(N, dom.gamma)
        nz = N > 0
        G[nz] = Gsum[nz] / N[nz]
        R = np.zeros((nS + 1, nA))
        R[seen] = Rsum[seen] / n_eff[seen]
        rmin = float(data["r"].min())
        m.rmin, m.rmax = rmin, float(data["r"].max())
        P[~seen, T] = 1.0
        R[~seen] = rmin
        P[T, :, :] = 0.0
        P[T, :, T] = 1.0
        R[T, :] = 0.0
        m.P, m.G, m.R = P, G, R
        m.PG = P * G
        # reward channels
        m.Rc = {}
        for c in (chan if chan is not None else dom.chan):
            cs = np.zeros((nS + 1, nA))
            np.add.at(cs, (s, a), w * data[c])

def value_iteration(m, R=None, mask=None, tol=1e-9, max_iter=20000, penalty=None):
    R = m.R if R is None else R
    if penalty is not None:
        R = R - penalty
    V = np.zeros(m.nS + 1)
    for _ in range(max_iter):
        Q = _q(m, V, R)
        if mask is not None:
            Q = np.where(mask, Q, -1e18)
        Vn = Q.max(1)
        Vn[m.nS] = 0.0
        if np.abs(Vn - V).max() < tol:
            V = Vn
            break
        V = Vn
    Q = _q(m, V, R)
    if mask is not None:
        Q = np.where(mask, Q, -1e18)
    pi = Q.argmax(1)[:m.nS]
    return pi, V, Q


def q_learning(m, rng, steps, eps_fn=eps_exp, alpha0=1.0, alpha_min=0.02,
                q0=0.0, mask=None, n_ckpt=25, max_len=200, ckpt_fn=None):
    nS, nA = m.nS, m.nA
    ckpt_fn = ckpt_fn or (lambda p: J(m, p))
    Q = np.full((nS + 1, nA), q0)
    Q[nS] = 0.0
    cnt = np.zeros((nS + 1, nA))
    smp = Sampler(m, rng)
    ck = np.unique(np.linspace(0, steps, n_ckpt + 1).astype(int))
    curve = []
    s, ep_t = smp.start(), 0
    ci = 0
    for k in range(steps + 1):
        if ci < len(ck) and k == ck[ci]:
            pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
            curve.append((k, ckpt_fn(pi)))
            ci += 1
        if k == steps:
            break
        if rng.random() < eps_fn(k, steps):
            a = _explore(rng, s, nA, mask)
        else:
            a = _greedy(Q, s, mask)
        s2, r, g = smp.step(s, a)
        tgt = r + (0.0 if s2 == nS else g * Q[s2].max() if mask is None
                    else g * np.where(mask[s2], Q[s2], -1e18).max())
        cnt[s, a] += 1
        al = max(alpha_min, alpha0 / (1.0 + cnt[s, a] ** 0.7))
        Q[s, a] += al * (tgt - Q[s, a])
        ep_t += 1
        if s2 == nS or ep_t >= max_len:
            s, ep_t = smp.start(), 0
        else:
            s = s2
    pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
    return pi, Q, np.array(curve)

          incremental-average updates."""

          curve = []
          used, ci = 0, 0
          while True:
              while ci < len(ck) and used >= ck[ci]:
                  pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
                  curve.append((ck[ci], ckpt_fn(pi)))
                  ci += 1
              if used >= steps:
                  break
              s = smp.start()
              traj = []
              for _ in range(max_len):
                  if rng.random() < eps_fn(used + len(traj), steps):
                      a = _explore(rng, s, nA, mask)
                  else:
                      a = _greedy(Q, s, mask)
                  s2, r, g = smp.step(s, a)
                  traj.append((s, a, r, g))
                  s = s2
                  if s2 == nS:
                      break
              used += len(traj)
              # returns, backwards; first-visit
              Gret = 0.0
              rets = []
              for (s_, a_, r_, g_) in reversed(traj):
                  Gret = r_ + g_ * Gret
                  rets.append(Gret)
              rets.reverse()
              seen = set()
              for (s_, a_, _, _), G_ in zip(traj, rets):
                  if (s_, a_) in seen:
                      continue
                  seen.add((s_, a_))
                  N[s_, a_] += 1
                  Q[s_, a_] += (G_ - Q[s_, a_]) / N[s_, a_]
          pi = np.array([_greedy(Q, x, mask) for x in range(nS)])
